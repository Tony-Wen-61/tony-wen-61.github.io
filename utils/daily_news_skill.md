# 智能体技能规范：生成每日快讯博客文章

[Description: 载入此技能规范，以自动执行每日新闻的聚合抓取、翻译提炼、严格去重合并、以及最终 Hugo 博客文章的编译生成。]

## 运行上下文与前置条件
- **工作区根目录 (Workspace Root)**：目标 Hugo 项目的根目录。
- **运行环境**：已安装 `requests` 依赖的 Python 环境，以及 `hugo` CLI 命令行工具。
- **动态变量 (Variables)**：
  - `DATE_STR`：当前本地日期，格式为 `YYYY-MM-DD`（例如：`2026-06-12`）。
  - `DATETIME_ISO`：当前本地时间戳，符合 ISO-8601 标准且指定为北京时间东八区（例如：`2026-06-12T15:00:00+08:00`）。

---

## 执行管道流 (Execution Pipeline)

### 第一步：执行新闻抓取脚本
在工作区根目录下执行以下命令行，抓取最新新闻并缓存（支持传入可选的目标日期参数以抓取历史新闻）：
```bash
# 抓取当天（默认过去 24 小时）：
uv run utils/daily_news.py

# 抓取指定历史日期（例如 2026-06-11，精准过滤北京时间当天的内容）：
uv run utils/daily_news.py {DATE_STR}
```
*结果验证*：确认已成功在本地生成以指定日期命名的缓存文件 `utils/scratch/raw_news-{DATE_STR}.json`，且内容为按新闻分类组织的合规 JSON 数据。

### 第二步：编译、提炼与生成博文
读取 `utils/scratch/raw_news-{DATE_STR}.json` 中的原始数据，由大模型（LLM）将其翻译、去重并汇总，在 `content/posts/daily-news-{DATE_STR}.md` 路径下生成 Hugo 文章。

在处理数据时，请将以下 **Prompt 限制与系统级指令** 注入至大模型上下文（LLM Context）中：

#### [系统级博文提炼与排版指令]
1. **头部 Front Matter 格式**：文章开头必须包含以下精确的 TOML 配置块（包含「每日快讯」栏目简要介绍作为 `description`）：
   ```toml
   +++
   title = "每日快讯 | {DATE_STR}"
   date = "{DATETIME_ISO}"
   author = "Antigravity"
   description = "依托 AI 对全球多源权威数据进行智能抓取、翻译与筛选合并，致力于过滤低价值杂讯，用最少的时间掌握当日核心动态。"
   draft = false
   tags = ["每日新闻","AI生成"]
   categories = ["每日新闻"]
   ShowToc = true
   TocOpen = false
   +++
   ```
2. **“足够重磅”筛选原则**：严禁采用固定的最大条数限制。必须完全根据每个事件的“全球/全国级别影响力及重磅程度”动态筛选。各板块精确定位如下：
   - **`## 🌍 国际新闻`**：仅筛选重大地缘政治事件、核心多边谈判，或美、中、欧、俄、日、朝、韩、英等核心国家/地区的重要动向。过滤局部冲突、治安骚乱、个别常规体育比赛。
   - **`## 🐼 国内新闻`**：仅筛选全国性重磅、高影响力的事件或决策，如国家级重大政策出台、国家核心会议部署、国家级行业权威数据，或全国性重大灾害警告。过滤地方事故、常规商业动态或普通协会声明。
   - **`## 💼 商业财经`**：仅筛选对全球或国家市场有重大影响力的财经新闻，如万亿级企业里程碑（如 SpaceX 的 IPO 与影子盘）、大宗商品市场剧变（如国际油价大跌）、主要央行核心货币政策倾向，或全球核心人物重大财经听证会。过滤常规个股波动、单一企业常规盈亏 and 每日中间价。
   - **`## 🚀 AI科技`**：仅筛选具备行业里程碑意义的重磅科技进展，如物理 AI/具身智能超 1 亿美元的战略融资、前沿大模型与生成算法范式突破（如音频推理综述、物理视频生成 NEWTON）、以及权威高难 Agent 能力评测结果。过滤常规软件升级、配件折价和普通开发小工具。
3. **跨源去重与链接合并**：若多个数据源报道了同一重磅事件（如 SpaceX IPO、美伊谈判进展、英国防长辞职、全球厄尔尼诺形成、极难 Agent 评测等），**必须合并为单条列表项**。英文标题翻译为精炼的中文，并在列表项末尾汇总所有信源链接：`| [信源A](链接) / [信源B](链接) / [信源C](链接)`。
4. **绝对纯净输出**：除了文章头部的 Front Matter 之外，博文正文中不得包含任何寒暄性的前言引导语、总结性结语、友情提示或额外的免责声明（栏目介绍已统一置于 front matter 的 description 中）。直接输出板块标题及列表项目。

### 第三步：本地静态编译与预览

1. **静态编译校验**：
   在工作区根目录下执行以下指令，确保全站编译成功且无任何警告报错：
   ```bash
   hugo --minify
   ```
   *校验成功标志*：命令执行成功退出（Exit Code 为 0），终端显示编译完成页面数量。

2. **可选本地网页预览**：
   若需人工检查页面视觉效果，在工作区根目录下启动本地预览服务器：
   ```bash
   hugo server
   ```
   启动后，访问本地浏览器地址 `http://localhost:1313/` 实时核对排版与链接状态。

---

### 第四步：推送发布至 GitHub Pages

> [!IMPORTANT]
> **授权约束**：在执行第四步的 Git 命令行操作之前，智能体（Agent）**必须先向用户询问并获取明确的同意与授权**。未获得用户许可，严禁执行以下推送发布命令。

在工作区根目录下，运行以下 Git 命令行，将编译后生成的 `public/` 静态网页内容提交并推送至 GitHub 仓库：
```bash
# 1. 暂存 public 目录下所有新增、修改与删除的文件
git -C public add -A

# 2. 提交更改并附带日期说明
git -C public commit -m "自动更新每日快讯: {DATE_STR}"

# 3. 推送提交至 GitHub 仓库的 main 分支以触发发布
git -C public push origin main
```
